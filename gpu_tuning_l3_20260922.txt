OpenMX 4.0 AMD GPU tuning / -runtestL3 validation
Validation: 2026-09-22 to 2026-09-23 (JST)

Scope
  CPU numerical paths and build flags are unchanged. GPU-only changes cover
  energy/force reductions, device-side Force3 integration, HIP orbital tiling,
  large collinear cluster transforms and device eigenvector reuse, multi-k
  scheduling and noncollinear eigenvector reuse, and DC-LNO GPU dispatch.
  Cluster VRAM preflight accounts for simultaneous roots and MAGMA scratch.
  If only one spin fits, GPU spin solves run in sequence and release device
  workspaces between spins, preserving compact host eigenvectors for DM;
  DC-LNO returns MAGMA workspaces at its existing SCF release point.
  On shared GPUs its all-rank dispatch applies below dimension 2048; larger
  local matrices retain one GPU owner while other ranks use the existing CPU solver.
  DS_VNA pair batches shrink to fit device memory. HVNA computes its full
  mapped-array footprint and admits ranks in turns when necessary.
  Large EH0 batches (maximum >=8192 pairs/rank) run one rank per physical
  GPU at a time, including their mappings; small batches remain concurrent.
  OPENMX_EH0_GPU_CONCURRENCY=0 disables this; positive values set concurrency.
  No MAGMA algorithm/crossover change or new eigensolver backend was retained.

Configuration
  AMD Radeon RX 9060 XT (gfx1200), 16 GiB VRAM (16304 MiB reported).
  AMD Ryzen Threadripper 3970X, 32 physical cores, about 251 GiB host RAM.
  ROCm 7.2.0; Open MPI 5.0.9; AOCL 5.2.0; AOCC runtime 5.1.0.
  8 MPI ranks bound to cores; -nt 1; OMP/BLIS/OPENBLAS_NUM_THREADS=1.
  Original work/large3_example/*.dat and reference outputs were not edited.
  Each input was run via -runtestL3 in a separate MPI process and directory.
  Baseline commit: dccc11e315677a81511bec15b898b751e503c1bf.
  Baseline and candidate runs were serialized on the GPU for timing comparisons.
  Baseline uses the original runtime defaults. The final tuned configuration
  additionally sets GPU_MAX_HW_QUEUES=1,
  LIBOMPTARGET_AMDGPU_NUM_HSA_QUEUES=1 and HSA_ENABLE_SDMA=0.
  Reported before/after ratios therefore
  compare the original configuration with code plus runtime tuning. Earlier
  v1 pilots and separate matched-environment runs isolate individual changes.
  Timings are single-run elapsed times printed by runtestL3; small differences
  are not statistical claims. Candidate stages can still fall back to the
  existing CPU implementation when the shared 16 GiB GPU is too small.

Reproduction
  make -C source -j4 openmx \
    MPI_HOME=/home/kawai/opt/openmpi-rocmclang \
    AOCL_HOME=/opt/AMD/aocl/aocl-linux-aocc-5.2.0/aocc \
    AOCC_LIB=/opt/AMD/aocc-compiler-5.1.0/lib
  python3 tools/run_runtest_l3.py --binary source/openmx --ranks 8 \
    --output work/codex_l3_after \
    --env GPU_MAX_HW_QUEUES=1 --env LIBOMPTARGET_AMDGPU_NUM_HSA_QUEUES=1 \
    --env HSA_ENABLE_SDMA=0
  python3 tools/compare_runtest_l3.py --reference work/codex_l3_after
  python3 tools/compare_runtest_l3.py work/codex_l3_before work/codex_l3_after
  Use a fresh output directory for each run. The runner defaults to a 3600 s
  per-input limit and 16 GiB MemAvailable reserve, records interruptions, and
  continues through the suite. Its exit status is nonzero for incomplete runs.
  This validation allows Si1280-LNO and N1C999 up to 7200 s while retaining
  the memory guard; final/case_time_limits.json and any extended_monitor.json
  record that extension. Use --timeout 7200 for those long DC-LNO inputs.

Numerical checks
  Compare Utot, every Cartesian force component, atom identity/coordinates and
  integration grids. Absolute tolerances: 1e-7 Ha and 1e-7 Ha/bohr.
  The built-in force difference is a signed sum; it can hide cancellation and
  is not sufficient by itself. Bundled references round coordinates to five
  decimals, so reference-only coordinate comparisons allow one printed unit.
  Printed coordinates must agree exactly between baseline and candidate.
  The input files use only three SCF iterations; these checks establish
  regression agreement for those tests, not fully converged physical results.

Precision and runtime distinctions
  Ni63-O64's untouched baseline also differs from bundled reference forces
  by 1.1351082e-5 Ha/bohr (completed diagnostic with HSA_ENABLE_SDMA=0).
  The signed sum reported by the built-in test is only about 3.5e-9 and hides
  that component discrepancy. The separate matched-runtime comparison above
  includes timeouts for Ni63-O64 and GEL, so those ratios are unavailable.
  Comparing final Ni63-O64 with the completed untouched diagnostic gives
  abs dE=7.09e-11 Ha and max abs dF=2.487e-9 Ha/bohr. This case is not
  a 1e-7 reference-force pass.

  Fe1000's initial queue-limited v5 run differed from the bundled reference
  by 1.1707e-7 Ha and 1.66961e-7 Ha/bohr, just above the strict 1e-7 limits.
  The final table and native-transform control above report the actual final
  errors. The final/native force difference is 5.97849e-7 Ha/bohr. Native
  transforms also miss the reference tolerance (1.77635e-7 Ha/bohr), so
  OPENMX_CLUSTER_GPU_GEMM=0 does not by itself give a strict reference pass.
  A completed run alone does not establish numerical agreement.

  Fe1000 retains 8300 eigenstates after SCF1. The last up-spin state is at
  -0.14429778434630 Ha, chemical potential -0.15739059622626 Ha, T=900 K;
  its Fermi occupation is about 0.0100135. Final/native printed eigenvalues
  at the cutoff agree, but sampled restart density-matrix entries differ by
  up to 1.67e-5. Sensitivity to the eigenstate cutoff is a plausible explanation
  for the force differences; these observations do not prove that cause.
  The input, state-count rule and CPU numerical paths were preserved.
  A second run of the same final binary and relevant settings (fe-repeat/)
  completed in 690.44 s. It differs from the first final run by 2.18e-10 Ha
  and 2.03576e-7 Ha/bohr (400 force components exceed 1e-7); its reference
  errors are 1.15804e-7 Ha and 5.97364e-7 Ha/bohr. Thus Fe1000 does not
  establish reproducibility at the strict 1e-7 force threshold, even without
  changing the transform setting. No claim of a resolved numerical cause
  or a strict Fe1000 pass is made.

  With eight MPI ranks sharing this GPU, earlier default-runtime attempts
  spent many minutes inside HIP/OpenMP copies or kernel waits. SDMA=0 alone
  did not remove the Fe1000 EH0 wait; queues=1 alone completed Fe1000 but
  left a Pt500 HNL host-to-device copy waiting. Combining both settings
  removed those observed force-copy waits in subsequent C1000 testing;
  physical-GPU EH0 admission then completed its total-energy calculation.
  These observations do not establish a driver root cause. The executable
  does not force ROCm environment variables; the final launch settings and
  exact binary are recorded in command.json. Earlier diagnostic runs with
  debugger attachment are excluded from the final timing table.

  The original Fe1000 failed with MAGMA info=-113 (device allocation failure),
  while host MemAvailable remained at least 169 GiB. The new serial-spin
  capacity path completed Fe1000; that completion does not remove the
  reference-precision caveat. N1C999 needed an extended limit and finished
  at 6179.94 s with reference checks passing. Its original run was stopped
  at 1321.54 s, so no speedup is claimed for it.

Rejected optimization trials
  Lowering the MAGMA DSYTRD GPU crossover from 3000 to 1536 did not improve
  the observed N1C999 run. A separate DC-LNO hipSOLVER trial took 375.32 s
  on CG15c versus 238.76 s for the original executable. Both experiments
  were removed. The original MAGMA algorithm/crossover and source remain.
