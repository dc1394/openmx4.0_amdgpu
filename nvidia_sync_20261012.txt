Output policy
-------------
GPU diagnostics now use the input's existing level.of.stdout:
  1 (default): normal OpenMX progress and GPU suffixes, GPU initialization
               failure and dense GPU-to-CPU diagonalization notices.
  2: also workspace/cache plans, precision configuration/transitions,
     individual-stage fallbacks and solver retries.
  3: also per-SCF, per-k-point and per-rank refinement, warm-start and
     low-memory details.

Fatal errors and invalid-setting warnings remain visible. Explicit verbose
and profile environment settings retain their diagnostics regardless of
the stdout level. Output guards never enclose numerical state changes or
collective participation. Once-only notices record a notice only when it
is actually printed. Tile plans are reported when the batch count changes
or the workspace changes by more than 1/16, and at every size change at 3.

source/openmx_stdout_level.h is identical to the NVIDIA header. GPU modules
without openmx_common.h use a weak reference to the same level_stdout;
standalone harnesses without that variable retain level-3 output. The final
executable has a strong level_stdout definition from OpenMX. Six object
rules list the header as a dependency.

Density workspace and fallback
------------------------------
The density dispatch now preflights the cached on-the-fly arena against
free GPU memory minus the same 256 MiB reserve used by runtime allocation.
The AMD planner batches whole atoms and already enlarges a batch beyond
the configured bound to accommodate one large atom. NVIDIA's pair-batch
workspace growth was therefore not copied into the different AMD layout.

Admission counts share the existing preparation allreduce; no additional
preparation collective or node communicator is created. Ranks with no
atoms neither veto admission nor inflate fallback counts. If both all-rank
paths and the single-owner GPU service are unavailable, capable ranks keep
their local GPU path and only declined ranks run the original CPU loop.
Runtime GPU failures are counted with a shared nonblocking allreduce,
completed after density communication. Level 2 reports changes in the
fallback census; level 3 adds individual workspace shortages. These
communications do not depend on stdout level or rank-local admission.

Preflight is a memory snapshot. Peer allocations can still cause runtime
failure; the original locked allocation, partial-result cleanup and CPU
redo remain authoritative.

Real mixed density fallback
---------------------------
The same 32-Si collinear cluster fixture was run at levels 1, 2 and 3 with
rank 1's local and legacy OTF density routes disabled. A 32768 MiB admission
reserve on rank 0 rejects the single-owner service without allocating any
extra GPU memory. Capable ranks retain their GPU density kernels.

All three runs completed and matched the baseline full-GPU energy/forces:
maximum energy difference 9.95e-13 Ha, force difference 1.00e-12 Ha/bohr
(rounded). Explicit OPENMX_BAND_PROFILE=1 produced profiles at every level.
Each density call had all eight ranks: initially two CPU/six GPU ranks,
then one CPU/seven GPU ranks in the last call. Levels 2 and 3 each report
exactly these two census changes; level 1 reports neither. No GPU/MPI
failure or hang occurred. This validates the actual mixed dispatch and
its stdout-independent communication, in addition to the host failure tests.

Coverage limits
---------------
This validation uses three representative L3 cases, two CPU-only L3 cases
and the isolated stdout/mixed-density fixtures. It is not a rerun of all
S/L/L2/L3 inputs. Real GPU tests use one gfx1200 device shared by eight
ranks; admission of multiple physical GPUs is retained but was not tested
on multi-GPU hardware. Workspace shortage and device failure cases also
use host stubs; the real mixed test rejects admission through existing
environment controls. The three-SCF regression inputs are intentionally
not convergence benchmarks.
