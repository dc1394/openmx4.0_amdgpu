GEMMul8 v3.5.2 integration, 2026-10-05
====================================

Versions and scope
------------------
Old submodule: v3.4.4, ce56e4228881df97782804d4d5dad9125d9a6416
New submodule: v3.5.2, 603b52363715796a0af5e4aa1ed8d386349b4251
Release: https://github.com/RIKEN-RCCS/GEMMul8/releases/tag/v3.5.2

The submodule and GEMMUL8_COMMIT build pin select the same upstream release.
The upstream checkout has no tracked local modifications. OpenMX's existing
INT8 explicit instantiations remain compatible with the new public API and
internal headers, including grouped CRT reconstruction. FP8 is not used by
the existing OpenMX adapter. CPU computation sources are unchanged.

The build now generates/includes dependency files for the embedded GEMMul8
implementation and configuration objects. Changes to implementation headers
therefore rebuild the kernels. gemmul8-clean also removes the configuration
object and dependency files. A dry run with crt_tree.hpp treated as newer
confirmed recompilation and re-archiving; an ordinary incremental dry run
did not rebuild GEMMul8. Existing checkouts must select the recorded submodule
with git submodule update --init --recursive before building.

Standalone numerical checks
---------------------------
tools/check_gemmul8_hip.cu tests all eight instantiated operations against
native hipBLAS FP64: DGEMM, ZGEMM, DSYMM, ZHEMM, DSYR2K, ZHER2K, DTRMM, ZTRMM.
It checks transpose/conjugate transpose, both sides/triangles, unit/non-unit
diagonals, nonzero alpha/beta, padded leading dimensions, and untouched data.

86/86 checks passed with INT8, num_moduli=15, accurate mode.
Maximum absolute difference: 4.588e-11.
Maximum max_abs_error/max(1,max_abs_reference): 5.242e-15.
Acceptance limit for that ratio: 2e-12; all outputs must be finite.
No workspace fallback was logged.

Large DGEMM: 4097 x 2049 x 2049, unblocked work size 470915581 bytes.
Large ZGEMM: 2049 x 2049 x 2049, unblocked work size 565259517 bytes.
Both exceeded the 268435456-byte bridge cap and passed with blocking.
Two additional checks disabled GEMMul8 through the OpenMX input-switch API
and matched native hipBLAS exactly.
